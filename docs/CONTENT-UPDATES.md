# Content without rebuilding (Шорашим)

Course content is not built into the program. Lessons, cards, quiz
questions, the interview trainer, prayers, quotes and calendar texts are
plain JSON files in `content/<lang>/`, read when the app starts
(src/content_store.rs). Fixing or adding a card means editing a JSON file.
Rust is not compiled again.

## Where the files are

| | Path |
|---|---|
| In the repo | `content/ru/…` and, when ready, `content/en/…` (same file names, same ids) |
| On a user's computer | `%LOCALAPPDATA%\Programs\Shorashim\content\<lang>\…`, beside `shorashim.exe` |

```text
content/ru/manifest.json            contentVersion, minAppVersion, list of sections
content/ru/sections/NN-<id>.json    lessons, cards, quiz questions (docs/CONTENT-SCHEMA.md)
content/ru/interview.json           «Тренажёр собеседования» (generated by tools/interview/build_content.py)
content/ru/prayers.json             «Молитвы»
content/ru/quotes.json              «Цитата дня»
content/ru/calendar/*.json          calendar texts and the city list
```

The app looks for `content\` in this order: the folder in
`SHORASHIM_CONTENT_DIR` (when set, only there), the folder of the exe, then
the source tree it was built from (so `cargo run` and tests use the repo's
`content/`). The 3D models, images, fonts and the app's own interface text
stay built in.

## Fix a card in a few minutes

1. Edit the JSON in `content/ru/`, for example a card's `front` / `back` in
   `content/ru/sections/03-shabbat.json`. Never change or reuse an `id`:
   progress is stored under ids. A new card gets a new id. A removed id is
   ignored by old progress.
2. Bump `contentVersion` in `content/ru/manifest.json` (`2026-11-24`, a
   second change that day `2026-11-24.2`).
3. Check the files:
   ```sh
   tools/validate-content.sh              # = shorashim-ctl validate-content content
   ```
   It prints `OK …: версия …, N уроков, N карточек…`, or the file, line and
   what is wrong, for example
   `ОШИБКА content/ru/sections/04-kashrut.json: строка 3, позиция 3: пропущена запятая или закрывающая скобка }`.
   On Windows the same check is `shorashim-ctl.exe validate-content`.
4. See it in the app by restarting it. `cargo run` reads the repo's
   `content/` directly. In a running app, `shorashim-ctl reload-content`
   re-reads the files without a restart (control mode, docs/AUTOMATION.md).
   On a Windows test laptop, edit the files in
   `%LOCALAPPDATA%\Programs\Shorashim\content\ru\` and restart the app.
5. Commit and open a PR as usual. CI runs the same check
   (`validate-content`, `validate-parity`) and the content tests
   (`cargo test`: no «Библия / Ветхий Завет» framing, bank sizes, ids, etc.).

## Language parity (`content/en` vs `content/ru`)

English course files may appear gradually. Until `content/en/manifest.json`
exists, CI prints `SKIP` and exits 0. Once the folder is there, every
language must keep the **same JSON files**, the **same ids** (sections,
lessons, cards, questions, prayers, interview items, calendar days and
parashot — progress is stored under those ids) and the **same JSON shape**:
a field present in Russian must be present in English, with the same type.
Array lengths of id-bearing lists must match. Extra English keys are
allowed. Do not rename, reuse or drop an id; a new card gets a new id.

Check both languages:

```sh
tools/validate-content.sh content            # Russian (default)
shorashim-ctl validate-content content --lang en
shorashim-ctl validate-parity content        # files, ids, fields; SKIP if no en/
```

A failure names the relative file and the missing id or field, for example
`ОШИБКА sections/03-shabbat.json: id «s03-l02» is in ru but not in en`.
Switching the interface language in «Настройки» loads `content/<lang>/`;
if those files are missing or broken, the previous language and content
stay. `SHORASHIM_LANG=en|ru` overrides the language for one run
(screenshots, tests) and does not write the profile.

## Ship a content fix (installer only)

People get the app only as **`Shorashim-Setup.exe`**: a small setup program
with the app, `content/`, music and licences appended to it. Running it
installs (or updates) everything into `%LOCALAPPDATA%\Programs\Shorashim`.
The `content` folder is replaced whole, so removed files do not linger.
Progress (`%APPDATA%\Shorashim\progress.json`) is never touched.

For a content-only fix, repack the last setup with the new `content/`. This
takes seconds on any OS and needs no Rust build:

```sh
python3 tools/make_setup.py --from Shorashim-Setup.exe --content content \
    --out dist/Shorashim-Setup.exe
python3 tools/make_setup.py --list dist/Shorashim-Setup.exe   # app and content versions
```

`Shorashim-Setup.exe` is the latest release asset or the CI artifact
«Shorashim-Setup». The programs inside it stay exactly as they were, and only the
course files change. If the new content needs a newer program (a new field
the old app does not know), raise `minAppVersion`. An older app then shows a
clear message instead of misreading the files, and the fix ships with a full
build.

A full build (what CI does on Windows after `cargo build --release`):

```sh
python tools/make_setup.py --stub target/release/shorashim-setup.exe \
    --exe target/release/shorashim.exe --ctl target/release/shorashim-ctl.exe \
    --content content --music assets/music --extra LICENSE NOTICE \
    --out dist/Shorashim-Setup.exe
```

Publishing a release is a separate, explicit step. Neither tool uploads
anything.

Setup options: `--quiet` (no question), `--no-launch` (install only).

## If a file is broken on a user's computer

The app does not crash. It opens a small window «Не удалось открыть
материалы курса» with the file name, the line and what is wrong. The window
has «Открыть папку» and «Закрыть» buttons. If the `content` folder is
missing, the window says where it looked. Running `Shorashim-Setup.exe` again
puts the files back. Progress is stored separately and is not affected.

## Versions

- `contentVersion`: bumped with every content change. It is shown by
  `validate-content` and by the setup.
- `minAppVersion`: the oldest app that can read the files. An older app
  refuses them with a message naming `manifest.json`.
- `contentFormat`: 1. A future layout change raises it, and older apps then
  ask to be updated.
